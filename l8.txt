20.Back up the current firewall configuration.
Backup:
sudo iptables-save | sudo tee ~/iptables-backup.txt
Start a subscriber for the local SmartFactory topic:
mosquitto_sub -h localhost -p 1883 -t 'smartfactory/machine01/#' -v
From another terminal, publish a legitimate dummy reading:
mosquitto_pub -h localhost -p 1883 -t 'smartfactory/machine01/temperature' -m '24.00'
Demonstrate false-data/replay-style injection on the same owned topic:
mosquitto_pub -h localhost -p 1883 -t 'smartfactory/machine01/temperature' -m '99.99'
mosquitto_pub -h localhost -p 1883 -t 'smartfactory/machine01/temperature' -m '24.00'
21.	Observe that a subscriber cannot infer authenticity merely from the topic/payload.
Apply a temporary firewall rule to block inbound MQTT on the lab host:
sudo iptables -I INPUT 1 -p tcp --dport 1883 -j DROP
22.	From a second authorized lab VM, verify that new remote connections to port 1883 are blocked. Localhost behavior may differ because loopback traffic is local.
For an isolated lab subnet, allow only the authorized subnet before the DROP rule (example VirtualBox NAT subnet):
sudo iptables -I INPUT 1 -p tcp -s 10.0.2.0/24 --dport 1883 -j ACCEPT
Restore the original firewall after the exercise:
sudo iptables-restore < ~/iptables-backup.txt
23.	Document attack, observed impact, control and retest result.
